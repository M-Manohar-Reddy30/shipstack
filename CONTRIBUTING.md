# Contributing to SHIPSTACK

Thanks for your interest in contributing to SHIPSTACK.

SHIPSTACK aims to help developers understand how real full-stack software is
designed, built, tested, secured, deployed, observed, and scaled.

## Before Contributing

Please:

1. Read the README.
2. Search existing issues and pull requests.
3. Open an issue before starting a large change.
4. Keep contributions focused and technically useful.

## Good Contributions

Examples include:

- New engineering scenarios
- Architecture patterns
- Security examples
- Testing strategies
- Production checklists
- Deployment examples
- Documentation improvements
- Real-world failure scenarios
- Developer tooling

## Pull Requests

A good pull request should:

- Explain what changed.
- Explain why the change is useful.
- Include documentation where appropriate.
- Include tests when applicable.
- Avoid unrelated changes.

## Engineering Principle

Prefer evidence over claims.

If you describe something as secure, scalable, reliable, or production-ready,
explain how that claim can be tested or verified.
